# 多人同时用：并发、@ 通知、引用回溯

群里三个人同时发话，以前是一个跑完下一个才动；回复只往群里丢一句，群静音就没人知道；
选中一条旧消息（尤其带图的）说「你重新做这个」，机器人压根不知道「这个」是什么。

这三件事现在都改了。这份文档说清楚它现在怎么动、怎么调、怎么退。

## 一、并发：同一个人串行，不同的人并行

| 情况 | 以前 | 现在 |
| --- | --- | --- |
| 甲在跑，乙发话 | 排队等甲跑完 | 乙立刻开跑（还有空位的话） |
| 甲在跑，甲又发一句 | 排队 | 仍然排队——同一个人的任务必须按顺序，不然会话会被写乱 |
| 三个人的活都在跑，丁发话 | 排队 | 排队，但空出一个位就自动接上，不用再发一遍 |

- 默认上限 **3 个**同时在跑（`config.json` 的 `max_concurrent`）。
- 排队时会明说：`⏳ 现在 3 个任务同时在跑，这个排上队了，空出来自动接上。`
  同一个人排在别人后面时是 `⏳ 你前面还有 2 个在跑，这个排上队了，完了自动接上。`
- 为什么不是无限并发：agent 机是 600G2 那台小机器，一个任务就吃满一个模型连接，
  再叠额度也扛不住。3 是「够用且不炸」的值，机器换大了就往上调：

```jsonc
// /opt/feishu-bot/config.json
"max_concurrent": 3
```

改完 `systemctl restart feishu-bot.service`。想回到「一个一个来」就填 `1`。

进度卡的脚注会写 `在跑 2/3`，一眼看出现在是几路在跑。

## 二、回复 @ 发起人

群常年静音，不带 @ 的回复等于没回。现在：

- 群里：所有回复都带 `<at user_id="ou_xxx">`，被回的人手机上有红点。
- 私聊：不带 @（本来就有通知，@ 自己看着怪）。
- **结果卡也 @**：卡片的第一个元素就是 @ 那个人。卡片里用的是 `<at id=ou_xxx>`（卡片 markdown
  语法），文本消息用 `<at user_id=ou_xxx>`（富文本语法），两种写法不能混。
- **卡片是原地刷新的，刷新不推通知**。所以跑超过 30 秒的任务，除了刷新卡片，还会额外补一条
  短消息 `✅ 好了，在上一条卡片里（用时 1 分 20 秒）` 并 @ 他——否则他永远等不到提醒。

## 三、引用/回复一条旧消息

你按住某条消息「回复」再说「你重新做这个」，飞书事件里只带一个 `parent_id`，正文和图片都不在里面。
以前机器人拿不到，只能接着当前上下文瞎猜——你让它重做，它把上一轮的结论又贴一遍。

现在会**先回去把那条消息捞出来**：

| 被引用的是 | 机器人看到什么 |
| --- | --- |
| 文字 | 原文（最多 1200 字）+ 你这句话 |
| 图片 | **把那张图下载下来落到工作区**，跟直接发图走同一条路，模型真的用 `read_image` 打开看 |
| 文件 / 视频 / 语音 | 同样下载落盘，交给模型处理 |
| 富文本（post） | 拍平成文字，图记成 `[图片]` |
| 卡片（比如上一轮的结果卡） | 拍平成文字，能读到上一轮的结论 |
| 表情包 | `[表情包]` |

拼出来的任务长这样：

```
【用户发来一张图片，已存到工作目录】.feishu-inbox/img-20261101-131502.jpg（相对 /home/agent/work/…）

他附言：【他引用了（咪咪 发的）的一条图片消息，下面这张就是】

【他这句话】你重新做这个
```

拿不到那条消息（被撤回、太旧、没权限）时，会老实说一句「取不到」，不会装作看见。

**实测**：清空会话（`session=None`，没有任何上下文）后引用一张试卷照片问「什么科目」，
12 秒答「有机化学」——只能来自真的打开了那张图。

## 已知边界

- 一次只跟一条引用走：引用的消息里如果再套一条引用，只还原第一层。
- 被引用的图片仍然受 20MB 上限（`max_attachment_mb`）和 `.feishu-inbox/` 沙箱约束。
- 卡片 @ 用的是被回那个人的 `open_id`；他改过昵称不影响。

## 怎么退

三件事都在 `services/feishu-bot/bot.py` 一个文件里，回滚整个文件即可：

```bash
cp -p /opt/feishu-bot/bot.py.bak-before-at /opt/feishu-bot/bot.py
systemctl restart feishu-bot.service
```

只退并发：把 `max_concurrent` 改成 `1`，重启。
只退 @：删掉 `handle_inner` 里的 `reply()` 包装，把调用换回 `send(chat_id, …)`（40 处）。
只退引用：删掉 `handle_inner` 里 `quote_note` 那一段。
