# 飞书接单反馈与查询恢复修复

## 问题与行为

原生通道很快接单，但后续始终更新聊天历史中的旧卡片，工具执行期间没有新正文时，用户在底部看不到反馈。现在非重复成功接单会创建当前确认卡，并把后续 SSE 进度指向新卡。确认失败不改变任务已接收的事实；先订阅回复再发确认，避免确认 API 阻塞答案。

机器人记录回复订阅键，重启恢复；启动健康检查失败仍保留客户端，由订阅线程重连。确认使用有限进程内消息缓存去重，接单回执超时后的 duplicate 重试可补确认，保留明确的 inject/steer 意图。并发卡片创建和旧 SSE 更新使用 generation 检查，不能覆盖后接单的目标。进程重启不持久化确认去重缓存；上游事件幂等仍由通道 outbox 保证。

飞书绑定 agent 的网页问答工具请求明确失败并要求普通文字追问，不代答或批准；其他 agent 仍交给原处理器。`feishu_whoami` 保留成功的身份信息，但群列表查询失败会给出 `chats_error`，不误报为没有群。现有工具静态注册，无新增搜索协议。

## 验证

`pnpm test` 现在包含 TypeScript 测试、原生通道自检/HTTP 绑定问答测试，以及实际 Python 机器人入口测试。Python SDK/API 使用替代实现，覆盖超时重试、乱序卡片完成、订阅恢复及初始不可达后的恢复，不证明手机滚动或真实网络延迟。
